 # Java Developer — DSA 0 → Hero Roadmap

 > **Target:** Java Developer with 4 Years of Experience\
>  **Goal:** Build strong DSA fundamentals, pattern recognition, problem-solving ability, and interview readiness.\
>  **Total:** \~200 carefully ordered LeetCode problems\
>  **Approach:** Easy → Medium → Hard, with prerequisites and pattern combinations introduced progressively.

---

 ## 🎯 Roadmap Strategy

 This roadmap is **not a random collection of LeetCode problems**.

 The questions are ordered so that:

 1. Basic patterns are learned first.
2. Simple problems establish the pattern.
3. Medium problems introduce variations.
4. Multiple patterns are combined only after the individual patterns are covered.
5. Hard problems come after the required building blocks.
6. The final stage contains mixed-pattern interview problems.

 ### 4 Stages

```
Stage 1
Pattern Foundation
        ↓
Stage 2
Pattern Combination
        ↓
Stage 3
Interview Level
        ↓
Stage 4
Interview Simulation / Advanced
```

 # 🧠 Problem-Solving Process

 For every new problem, follow this process.

```
1. Understand the problem
        ↓
2. Identify input/output
        ↓
3. Write brute force idea
        ↓
4. Analyze time & space complexity
        ↓
5. Look for constraints
        ↓
6. Identify possible pattern
        ↓
7. Identify the invariant
        ↓
8. Implement
        ↓
9. Test edge cases
        ↓
10. Analyze complexity
        ↓
11. Re-solve without looking at code
```

 # 🔍 Pattern Recognition Questions

 When I see a new problem, ask:

 ### Array / String

```
Is the array sorted?
        ↓
Two Pointers / Binary Search
```

```
Do I need to remember previous values?
        ↓
HashMap / HashSet
```

```
Is the problem asking about a contiguous
subarray / substring?
        ↓
Sliding Window / Prefix Sum
```

```
Does the problem ask for subarray sum?
        ↓
Prefix Sum + HashMap
```

 ### Sliding Window

```
Contiguous range?
        ↓
Can I expand right?
        ↓
Can I shrink left?
        ↓
Sliding Window
```

 ### Binary Search

```
Is the data sorted?
        ↓
Binary Search
```

```
Is the answer monotonic?

Possible → Possible → Possible
Impossible → Impossible → Impossible

        ↓
Binary Search on Answer
```

 ### Linked List

```
Need middle / cycle / kth from end?
        ↓
Fast + Slow Pointers
```

```
Need reversal?
        ↓
Previous + Current + Next
```

 ### Stack

```
Need nearest greater/smaller element?
        ↓
Monotonic Stack
```

 ### Heap

```
Need Top K?
        ↓
Heap
```

```
Need median from streaming data?
        ↓
Two Heaps
```

 ### Tree

```
Need shortest level-based traversal?
        ↓
BFS
```

```
Need subtree information?
        ↓
DFS
```

```
Need information from children
before processing parent?
        ↓
Bottom-Up DFS
```

 ### Graph

```
Connected components?
        ↓
DFS / BFS / Union Find
```

```
Shortest path in unweighted graph?
        ↓
BFS
```

```
Shortest path with weighted edges?
        ↓
Dijkstra
```

```
Dependency ordering?
        ↓
Topological Sort
```

 ### DP

```
Same subproblem appears repeatedly?
        ↓
DP / Memoization
```

```
Can I define:

dp[i] = best answer up to i

        ↓
1D DP
```

```
Can I define:

dp[i][j] = answer using i and j

        ↓
2D DP
```

 ## Useful Java Patterns

 ### HashMap

```
Map<Integer, Integer> map = new HashMap<>();

map.put(value, map.getOrDefault(value, 0) + 1);
```

 ### HashSet

```
Set<Integer> set = new HashSet<>();

set.add(value);

if (set.contains(value)) {
    // ...
}
```

 ### Min Heap

```
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
```

 ### Max Heap

```
PriorityQueue<Integer> maxHeap =
        new PriorityQueue<>(Collections.reverseOrder());
```

 ### Deque

```
Deque<Integer> deque = new ArrayDeque<>();

deque.offerLast(value);
deque.pollFirst();
deque.peekFirst();
```

 ### Sorting


 # ⏱️ Complexity Targets

 For interview problems, learn to recognize the expected complexity.

 | Complexity | Typical Pattern |
| --- | --- |
| `O(1)` | HashMap lookup / direct access |
| `O(log n)` | Binary Search |
| `O(n)` | Two Pointers / Sliding Window |
| `O(n log n)` | Sorting / Heap |
| `O(n + m)` | Graph BFS / DFS |
| `O(V + E)` | Graph traversal |
| `O(n log k)` | Heap / Top K |
| `O(n²)` | Nested loops / basic DP |
| `O(2^n)` | Backtracking |
| `O(n × m)` | 2D DP |
| `O(E log V)` | Dijkstra |

 # 🔁 Revision Strategy

 Do not solve a problem once and forget it.

 Use this revision cycle:

```
Day 0
─────
Learn + Solve

Day 1
─────
Solve again without looking

Day 3
─────
Solve again

Day 7
─────
Solve again

Day 14
──────
Solve again

Day 30
──────
Final revision
```

 Use this rule:

```
If I cannot solve it:
    Review the pattern
    Understand the mistake
    Close the solution
    Re-code it myself
```

 # 🎯 When Should I Move to the Next Pattern?

 Move forward when you can:

 - Identify the pattern within \~5–10 minutes.
- Explain why the pattern applies.
- Write the solution without copying.
- Explain time complexity.
- Explain space complexity.
- Handle edge cases.
- Solve at least 2 variations of the pattern.
- Re-solve the problem after a few days.
